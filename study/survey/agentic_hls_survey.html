Survey · LLM and agentic HLS code generation · 2023 to Oct 2026

Agentic HLS Survey

Do HLS-specific agent pipelines still contribute anything when a general coding agent such as Claude Code, given the same knowledge and constraints, can do the job? This survey reviews about 40 HLS systems, the workflow-versus-agent literature in software engineering and RTL design, and our own HLSmith measurements, and answers that question as far as the evidence allows.

Compiled 2026-10-21 from web research on arXiv, conference and vendor pages, plus the c2hls / HLSmith study logs. Papers after mid-2026 are preprints and are marked as such. Numbers that could not be checked against the paper itself are marked unverified.

Short answer for the supervisor's question

His suspicion is half right, and nobody has tested the other half

What the evidence supports. Domain knowledge and resource requirements are where the large gains come from, in HLSmith's own ablations and across the field. With a frontier model and good tools, a plain general agent already does well on small and medium HLS kernels: an unmodified coding agent saturates HLS-Eval, and the UCLA AHRR study improves AutoSA GEMM designs with one. In software engineering and machine-learning engineering, minimal agents now match elaborate scaffolds, and compute-matched studies attribute most multi-agent gains to extra compute.

What nobody had shown. No published HLS paper compares a dedicated agentic flow against a general coding agent with the same model, knowledge, tools and budget. HLSmith's preprint compares against ChatHLS and zero-shot prompting; Agent Factories and the IBM QEC work use Claude Code but compare against no specialized system.

Our first such test (experiment C, matrix multiply, Opus 5.5). Given HLSmith's skill pack, DSP window and starting kernel, and the same budget of 12 Vitis checks, Claude Code on its own reaches the same cycle counts as HLSmith with an agent backend: 497K and 809K cycles against 591K, 792K and 836K, with logic capped at 80% for both. The free agent does it at about 3.5× the cost ($5–6 against $1.3–1.7 per run) and 3–5× the Vitis checks. Without the logic cap it looks better (481K–538K), but only by filling 80.3–97% of the chip's LUTs. So on this kernel the supervisor's suspicion holds for quality: HLSmith's flow adds nothing to quality that Claude Code cannot reach with the same knowledge. What the flow adds is lower cost, smaller designs and reliability.

Where a dedicated flow has defensible value, in order of strength of evidence:

  1. Guarantees from verification gates. In HLSmith's paper, all 154 of Sonnet's agentic results met timing and resource limits, against 18 of 26 zero-shot. Weak test oracles inflate pass rates by about 60% (AgRefactor). Verification is the part of a scaffold least likely to be absorbed by stronger models.
  2. Weaker and open models. In hardware, a 7B model doubles inside a validation pipeline (36.5% to 75.0%, ChipCraftBrain). On CVDP, wrapping models in a generic agent loop made every model worse, open models most. In HLS, the same scaffold with DeepSeek v4-flash reaches 91.6% all-pass against 0–28% zero-shot (Evidence-Driven agent).
  3. Cost and predictability. Bounded flows cost dollars per kernel; general-agent factories cost $26–299 per kernel (IBM) or millions of tokens per run (Agent Factories). But one 2026 study found a minimal long session cost 6.2× more than a structured harness, so cost has to be measured, not assumed.
  4. Search at scale. DSE gains in LLM-DSE, iDSE and Agent Factories come from search structure (tree search, evolutionary loops, ILP selection) around the model, not from free-form chat.

Recommended position. Present HLSmith's contribution as reusable HLS expertise plus verification-gated orchestration that makes it work across models at bounded cost, and show that with the matched general-agent baseline. Experiment C supports that framing and rules out the claim that HLSmith's agent loop produces better designs than Claude Code on matrix multiply. Whether the flow wins on harder kernels or with cheaper models (experiment D, and the stuck kernels) is still open.

The line between "multi-agent" and "general agent" is blurring. Agent Factories runs Claude Code, but inside a domain wrapper that decomposes kernels into sub-kernels and selects designs with an ILP. The useful distinction for the supervisor's question is who decides the next step: the designer's code (pipeline, fixed roles) or the model (general agent).

3 · Ablations that isolate structure

What the HLS literature actually shows about pipeline structure

Structure helps over a single call

  • LLM-DSE: zero-shot GPT-4o reaches 0.16× of AutoDSE; adding arbitrator, specialists, router and critic step by step gives 0.69×, 0.95×, 1.24×, 1.87×.
  • Evidence-Driven agent: zero-shot 0–28% all-pass; full workflow 87.9%. Three prior pipelines re-run with the same model and budget reach only 29–35%.
  • FPGAgent: with Qwen3-Coder-30B, functional rate 37% (base) to 67% (search and reflection).
  • HLSmith: agent loop meets limits in 154/154 Sonnet cells vs 18/26 zero-shot.

But the controls are against weak baselines

  • Every "structure helps" result above compares against zero-shot prompting or older pipelines, never against a general coding agent with the same tools.
  • LLM-DSE has no "single agent with the same tools" row; MAGE in RTL does, and that row closes half the gap (below).
  • FPGAgent never removes its retrieval, so knowledge and structure stay confounded.
  • HLSmith's own flash vs multi-step comparison is mixed: 1.03× vs 1.30× with selected expertise, 2.12× vs 1.58× with all expertise.

Results that cut the other way

  • Agentic-HLS: the agent is worse than the fine-tuned GNN it wraps.
  • HLSmith open-model pilot: the expertise library hurts a base Gemma model (0.50×) until the orchestrator is fine-tuned.
  • Agent Factories: more agents is not monotonic (8 agents 7.07×, 10 agents 6.53×).
  • Agentic HLS-Eval: a generic mini-swe-agent saturates correctness on 85 designs.

Knowledge, by contrast, has consistent support: HLSmith's expertise library gives 1.9–2.9× across five models, RAG adds 9–14 points in HLS-Repair and the Evidence-Driven agent, and RALAD's retrieval takes CodeLlama-7B from 0% to 30% synthesizable.

The pattern: the general-agent papers that report big gains still add domain structure (decomposition, selection, verification). That is the same kind of structure HLSmith provides, which is why a matched comparison is needed before anyone claims either side.

5 · Evidence from software engineering and RTL

When workflows beat agents, and when they stop mattering

General agents caught up

  • Anthropic's SWE-bench scaffold is a prompt plus two tools; mini-swe-agent (about 100 lines) is now the reference harness for model comparisons.
  • A single long OpenCode session matched or beat four ML-engineering harnesses on every backbone (62.5% vs 47.1% medals with GLM-5.2).
  • With compute normalized, single agents match or beat multi-agent systems; multi-agent gains shrink as models get stronger.
  • Coordination hurts sequential tasks by 39–70% and stops paying once a single agent passes about 45% (Google/DeepMind/MIT).

Workflows still won

  • Agentless beat agents on SWE-bench Lite in 2024 at a fraction of the cost (32.0% at $0.70 vs 18–27% at $1.1–2.5).
  • MAGE (RTL), same model: vanilla 72.4%, single agent 83.9%, multi-agent 93.6% on VerilogEval-V2.
  • ChipCraftBrain: a 7B model scores 36.5% alone and 75.0% in the validation pipeline; on hierarchical designs 50% vs 0% for Opus alone.
  • CVDP (NYU, 2026): naive agentic wrapping lowered every frontier model (e.g. Opus 4.6 50.7% → 43.5%; Kimi K2.5 47.4% → 21.7%).

What reviewers now expect

  • Cost-matched Pareto reporting against simple baselines (retry, best-of-k, single agent with the same compute).
  • A strong general-agent baseline with the same model, plus a "roles merged into one agent" ablation.
  • At least 5 runs with confidence intervals; single-run gains of 2–6 points can be noise.
  • A model sweep including a weak or open model, because scaffold and model effects interact.

Caution. Kernel-optimization agents without strong verifiers have been reward-hacked: the AI CUDA Engineer skipped correctness checks, and under hidden tests a frontier model's 1.43× geomean fell to 0.88×. HLS has no published reward-hacking audit yet.

Agent backend vs plain, inside HLSmith

On the same fixed bench (experiment A), the agent backend gains 2.2–8.5× where HLSmith says little (zero-shot, Base, Expertise rungs) and 1.3–2.2× once a resource requirement is in place. On Expertise + DSP floor the fastest agent-backend design (656K) uses 83% of the LUT and is over the cap; that run falls back to a 722K design its session synthesized (csim’d afterwards, it passes), a 1.4× gain. The cost per run is about the same ($1.21 plain vs $1.34–1.74 with the agent backend on the window rung; $2.13 vs $1.94–2.62 with the DSP floor). Plain HLSmith already gets most of the way.

What HLSmith's knowledge does for the agent

The same agent goes from 4.20M cycles (zero-shot) to 534K–722K with HLSmith's resource requirement and skills (best per rung, within the 80% LUT cap). Without the resource requirement, skills alone leave it at 9.6M. The knowledge and requirement are the large lever.

Experiment D, still open

The same free agent driven by DeepSeek v4-flash produced a valid in-window design in only 1 of 3 budget-matched runs (948K cycles). One unbounded run "won" with 292K cycles by switching to 18-bit fixed point that only works for inputs in [0, 1); the hardened bench rejects it. Plain HLSmith with DeepSeek on the same rung (experiment A) found no design in any of its 3 runs.

Experiment C: HLSmith with an agent backend vs Claude Code on its own, same knowledge and budget

Both sides use Opus 5.5, the same 138-skill refined pack, the same DSP window (6,317–7,219, 70–80% of the U280), the same starting kernel and bench, and an allowance of 12 Vitis checks run one at a time with a 1-hour csynth limit. Run 1 of the free agent had an unbounded budget and is shown for reference. Every design here passes the hardened bench (signed and wide-range inputs the agents never saw). The 80% LUT cap was applied afterwards to both sides; neither was told about it. It applies to every number on this page. One rule decides which design a run counts, on both sides: its fastest design that the run csim’d on the fixed bench, synthesized as the byte-identical kernel, fits the LUT cap and the rung’s DSP gate, and passes the hardened bench. With an agent backend this includes the checks its session ran itself, so a run can count a design other than HLSmith’s final. Quality: a tie

Under equal limits the two budget-matched free-agent runs (497K, 809K) bracket the agent backend's three (591K–836K). With two and three runs per side, neither is ahead.

Cost and footprint: HLSmith

HLSmith reaches its designs at about 3.5× lower cost and with a third or less of the Vitis checks, and its designs use 35–65% of the LUTs without being asked. The free agent's uncapped lead comes entirely from 80.3–97% LUT designs, over the cap.

What this rules out

On matrix multiply, HLSmith's flow does not produce better designs than Claude Code on its own given the same knowledge. A paper should not claim it does. The open questions are harder kernels, cheaper models, and variance over more runs.

Before submission. HLSmith's preprint gives two different headlines (138× in the abstract, 18.77× in the body), and its cost section could not be found. Reviewers who check, as this survey did, will notice.

7 · Threats to validity across the field

Weaknesses most papers share

  • csynth estimates as performance. Most papers report csynth cycles. LightningSim measured csynth-to-cosim errors of −40% to +685%, and "?" for designs with data-dependent control. In our study, SODA's own stencil designs cosim 4× slower than csynth suggests under Vitis 2023.2. Only ChatHLS, LAAFD, the Evidence-Driven agent and HLSmith gate on cosim.
  • No place and route. Resource caps at 80% of csynth estimates stand in for routability; AHRR is one of the few to use post-route period × cycles.
  • Weak correctness oracles. Hidden tests cut AgRefactor's public pass count by about 60%. Many testbenches are small or LLM-written. We hit this ourselves: our matrix-multiply bench used only inputs in [0, 1), and a DeepSeek free agent exploited it with 18-bit fixed-point arithmetic. A hardened bench with signed, wide-range, unseen inputs caught it, and confirmed every other headline design.
  • Weak baselines. Speedups over unoptimized code (up to 768×) are not comparable with speedups over experts. Only AHRR uses AutoSA; only LAAFD uses SODA.
  • Single runs and best-of-N. Variance appears only in C2HLSC, Agent Factories and HLSmith; Best@5 is common.
  • Sparse cost reporting. Dollars appear in LLM-DSE, LAAFD, C2HLSC and the IBM QEC paper; tokens in Agent Factories and the Evidence-Driven agent.
  • Confounded ablations. Scaffold, knowledge and model are almost never varied in a full factorial.
  • Inconsistent headlines. Abstract and body disagree in Agent Factories, HLSmith, RALAD, SAGE-HLS, ChatHLS, C2HLSC and HLStrans.
  • Saturated and public benchmarks. HLS-Eval is saturated by a generic agent; PolyBench, MachSuite and CHStone are decades old, with no contamination study for HLS.
8 · Recommendations

What to claim, and which experiments reviewers will expect

Claims the evidence supports

  1. HLSmith's expertise library and resource requirements are reusable knowledge that improve every model and every mode, including a general agent.
  2. Verification-gated orchestration guarantees feasible, correct designs (cosim-checked, within resource limits) where free agents and zero-shot do not.
  3. The flow makes cheaper and open models useful at bounded, predictable cost.

Claims to avoid until C and D finish

  • "HLSmith's agents outperform a general coding agent."
  • Any speedup over unoptimized code presented as a speedup over expert or compiler baselines.
  • csynth latency as performance for dataflow or data-dependent designs without cosim.

Experiments to run

  1. Matched general-agent baseline (C, D): same model, knowledge, tools and budget; report the Pareto of cycles against dollars and Vitis-hours.
  2. Factorial ablation: scaffold (none, plain flow, flow with an agent backend, Claude Code on its own) × knowledge (none, expertise) × model (frontier, cheap, open).
  3. Reliability: 5+ runs per cell, success counts, confidence intervals, pass^k.
  4. Measurement tiers: csynth, cosim or a validated fast simulator (LightningSim matched our cosims exactly on blocking-read designs), and place and route for the headline designs.
  5. Expert baselines: AutoSA for GEMM and LU, SODA (as generated and patched) for stencils, AutoDSE or HARP for pragma DSE.
  6. Hidden testbenches the agent never sees, and an audit of outliers for special-casing.
