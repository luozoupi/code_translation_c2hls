# Generated evidence interface

Files in this directory are included by `main.tex`. Headline result fragments
remain in a checked-in `pending` state until a fixed run set with a complete
configuration identifier exists. The separately generated archived
commercial-model results contain exploratory numbers and are prevented by
`claims.yaml` from serving as headline evidence.

The implementation-side generator is
`scripts/generate_hpca_paper_artifacts.py`. It first creates an immutable
directory named by the SHA-256 of the complete normalized result record. Publish the
four TeX fragments, the resource/Fmax CSV, and vector figures from exactly one such directory, and
check in its `artifact_manifest.json`, `claim_to_artifact_manifest.json`, and
`cell_provenance.json` as the corresponding validation records. Never mix files
across bundle checksums.

The current `commercial_snapshot.tex`, its macro file, and
`commercial_snapshot_manifest.json` are generated directly by
`scripts/generate_commercial_snapshot.py`; the source checksum is included in
that validation record. These archived results are explicitly exploratory
until independent CPU-output evidence can be joined to every selected row.

`historical_commercial_speedup.csv`,
`historical_commercial_setup_summary.csv`,
`historical_commercial_setup_table.tex`, the macro and validation-record files,
and `figures/historical_commercial_speedup.pdf` are generated by
`scripts/generate_historical_speedup_figure.py`.  The generator verifies that
`schema_records_v2.jsonl` contains the legacy schema as an exact byte prefix,
joins the relevant Sonnet flash and multi-step records to their COSIM replays,
summarizes all 14 distinct model/mode/skill configurations on the 26 kernels
with executed upstream baselines, and computes every cycle geometric mean on
the same seven-kernel all-setup success intersection.  It then applies the
documented partial-order filter separately within five model and workflow
families: both skilled settings must beat no-skill, and no-skill must beat
one-shot, while the two skilled settings may appear in either order.  It
selects the Opus no-skill-labeled result per kernel from the faster eligible
A/B repeat and keeps the genuine local dynamic-routing family separate from
the schema-labeled curated family.  Because the common set and plotted cases
are selected post hoc across archives that lack independent CPU-golden evidence
and matched run fingerprints, the table and figure are illustrative rather than
a matched ablation or headline result.

`trajectory_corpus_table.tex`, `trajectory_corpus_macros.tex`, and
`trajectory_corpus_manifest.json` are generated by
`scripts/generate_trajectory_corpus_snapshot.py`. The generator streams the
prepared SFT splits, counts the model labels saved by the original experiments, validates each row's
suite/quality/split and synthesis/CSIM fields, rejects duplicate or cross-split
targets, counts model-visible benchmark-specific cues, joins the cosim subsets by
benchmark/split/code hash, validates their observed/pass fields, and binds all
source files by SHA-256. These outputs prove that the current training-data
export exists; they do not independently verify the provider model, qualify the
data for training, or prove
a trained open-model result.

`student_transfer_table.tex` is a pending interface for a separate fixed,
held-out open-model test set. Its final generator must record the finalized training data and split,
base revision, SFT/reward checkpoints, controller configuration, and all run
IDs. Open-model rows must not be copied into `recovery_table.tex`, whose
comparison set is the HLSFactory-28 commercial-model/workflow evaluation.

`setup_tournament_table.tex`, `setup_router_table.tex`,

one-shot rows remain descriptive because their print-only CSim does not
compare output values; their cycles are not used as QoR denominators.  The
matrix therefore does not establish a fine-tuning gain without a matched
golden-checked unadapted-Qwen control.

explains the sequence but is not part of the final matched HLSFactory results;

The final result set supplies `recovery.pdf` and `budget.pdf`. The budget figure is
generated only from complete per-candidate event traces and combines
failure-aware QoR versus synthesis/token budget with the component ablation.
Copy those PDFs to `figures/` without modifying them; their renderer and font information
is recorded in `render_provenance.json`.

Required invariants:

1. no hand-entered result numbers;
2. every table cell maps to run IDs in `cell_provenance.json`, and every claim
   maps to its supporting inputs and outputs in `claim_to_artifact_manifest.json`;
3. failures remain explicit and count against valid-design rate/performance profiles;
4. predicted co-simulation skips never become measured cycles;
5. the complete run-configuration identifier is identical across macros,
   tables, plots, and the validation record;
6. all 28 baseline contracts and method outcomes are accounted for; each
   baseline and every reported successful winner passes the independent
   CPU-output check at both CSIM and COSIM, while failed outcomes stay visible;
7. expertise-off, selection-only, and skill-guided single-turn conditions repeat
   the declared optimization choices, while multi-step conditions differ only
   through their specified order-only, order+selection, and order+skill-guidance
   settings; all skill-guidance,
   corpus-readiness, SFT, reward-adaptation, and open-model non-inferiority claims follow their
   requirements specified before results are inspected;
8. intermediate budget points use authenticated Vitis HLS-estimated latency,
   are labeled as estimates, and include complete cumulative token/synthesis
   accounting; model-predicted or imputed co-simulation latency is forbidden,
   and the final winner uses CPU-checked COSIM-observed kernel cycles; and
9. BRAM, DSP, FF, LUT, URAM, and HLS-estimated Fmax cells come from the same
   authenticated selected-winner report as the corresponding cycle result;
10. no training row contains held-out kernels/families, benchmark-specific
    guidance, gold-relative context, or unremapped sensitive paths; and
11. every open-model cell names an exact base/checkpoint and uses the same fixed
    controller, skill-guidance configuration, candidate resource budget, and synthesis
    budget;
12. the fixed test kernels and families, inputs, training-data-producing model
    revision, workflow, prompts, and skill checksum are fixed before training
    or model selection; and
13. reward training freezes its objective and reports non-random missing-cosim
    handling; preference-based objectives require audited preference pairs.
