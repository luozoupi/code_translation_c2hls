# PASTA fast cosim (tapa-fast-cosim 0.0.20220816.dev1) on vanilla Vitis HLS kernels

PASTA's TAPA (SFU-HiAccel/pasta, TAPA 0.0.20240104.2) installs `tapa-fast-cosim>=0.0.20220514.dev1`, i.e. 0.0.20220816.dev1. That package is vendored in `vendor/tapa_fast_cosim/` (MIT; the untouched copy is in `vendor/.orig_tapa_fast_cosim/`). No TAPA `.xo` is used: `run_fast_cosim.py` csynths the kernel with c2hls `hls_eval` and feeds the Vitis HLS RTL to the templates.

## Patches (`diff -r vendor/.orig_tapa_fast_cosim vendor/tapa_fast_cosim`)

1. `MAX_AXI_BRAM_ADDR_WIDTH` 20 -> 22. This was the 1 MB-per-port limit; 22 bits give 4 MB, exactly one 1024x1024 fp32 array.
2. **Vivado project:**
   - the part is `xcu280-fsvh2892-2L-e` (was hard-coded `xc7vx485tffg1157-1`);
   - `.dat` (HLS memory init) files are added;
   - `xsim.elaborate.mt_level off`, which avoids the xelab SIGSEGV on large designs;
   - `debug_level off`, so there is no waveform.
3. **Timing markers:** `FASTCOSIM_START` / `FASTCOSIM_DONE` timestamps, plus an optional overall timeout (`FASTCOSIM_MAX_CYCLES`).
5. **Clock-edge counter:** a `fastcosim_cycles` counter in the testbench, printed at START and DONE. `rtl_cycles` is the counter difference; `rtl_cycles_from_time` (the $time difference / 4 ns) is a cross-check, and `rtl_cycles_consistent` flags disagreement.
4. **Heartbeat:** `FASTCOSIM_HEARTBEAT cycles=N` every `FASTCOSIM_HEARTBEAT_CYCLES` (default 100,000) simulated cycles, for progress and simulation speed.

## Correctness check

`gen_data.cpp` reproduces the bench testbench:
- the same `rand()` data;
- the same float golden accumulation;
- a `static_assert` that the size is 1024³ unless built for a self-test.

`C_out.bin` (the dumped memory of C's AXI RAM) is compared with the golden using the bench rule: an element is an error if |golden − C| > 0.001.

## Runs

- `sbatch --export=ALL,NAME=x,KERNEL=/path/kernel.cpp sbatch_fast_cosim.sh` (one node, 16 CPUs, 128 GB, 7 days).
- **Kept per run** in `NAME/`: summary, testbench, Vivado TCL, log excerpt. The work directory is deleted.

## Cycle-count fix (2026-10-09)

`selftest_bad` reported 65,046,000 cycles, 1,000× too many. It was generated by an earlier template that printed `$time` with `%0t`, which prints in the simulator's 1 ps precision, not the testbench's 1 ns unit. The driver then divided by a 4 ns clock.

The template had already moved to `%0d` (ns) when `selftest_good` and the 1024³ pilot `06_ladder_r3_L3` were generated, so their counts were right. Patch 5 removes the dependence on time units altogether.

Re-run with the fix (`selftest_*_v2`):

| Run | csynth | rtl_cycles | rtl_cycles_from_time | Check |
|---|---|---|---|---|
| good | 64,774 | 64,791 | 64,790 | 0 errors |
| bad | 65,030 | 65,047 | 65,046 | 1 error, caught |

The old `selftest_bad/fastcosim_summary.json` value is stale; its true count is 65,046.
