# Compact PE HLS-verified search

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** For `autosa_mm` (I=J=K=64 float, U280 3.33 ns), automatically enumerate compact PE×SIMD designs, HLS-verify each (csim + csynth), and rank by csynth latency — the AutoSA DSE *shape*, not AutoSA `kernel0`.

**Architecture:** AutoSA already automates polyhedral codegen + Odyssey/exhaustive search + HLS validate + rank. We do **not** call AutoSA. We enumerate a small `PeRecipe` grid, instantiate the compact stream skeleton (the 32×8 selected kernel is the template), run the existing `_run_synth_csim_cosim`, keep a `result.json` per point, and rank like AutoSA (`csim_pass && csynth_pass && architecture_ok`, sort by latency). LLM is not in the search loop.

**Tech Stack:** Python 3, existing `PeRecipe` / `autosa_flow_gates` / `c2hls._run_synth_csim_cosim`, pytest, Vitis HLS 2023.2, U280 `xcu280-fsvh2892-2L-e` 3.33 ns.

**Locked:** Aug 18 slide 16×4 story stays 4285 vs 4228. This search does not overwrite `autosa_mm` recipe or `20260830_mmflow`. Cosim off. Do not emit AutoSA `kernel0`.

## What AutoSA automates (and what we copy)

AutoSA is a **compiler plus a search**, then **HLS is the score**.

| AutoSA stage | What it does | HLS-verified? |
|--------------|--------------|---------------|
| Polyhedral codegen | C nest → systolic `kernel0` (space-time, PE array, interconnect, SIMD pack) | no — it is a generator |
| Odyssey | ILP / model over `array_part`, latency hiding, SIMD, resource cap | no — predicted latency |
| Exhaustive | discrete space-time points → `candidates.jsonl` (`sa_sizes`) | no |
| **Validate** | for each recorded point: codegen → **csim + csynth** | **yes** |
| Rank | keep `hls_csim_pass && hls_csynth_pass`, sort by `csynth_latency` | yes |
| Impl / xclbin | optional bitstream (out of this plan) | later |

Their validate worker (`AutoSA/scripts/pc2/dse/validation/run_kernel_hls_validate.sbatch.sh`) is the piece we want: **every search point gets a terminal `result.json`, failures are kept, ranking ignores anything that did not csim+csynth.**

Our agent flow today is the opposite: **one recipe, one LLM rewrite, one HLS score**. That is how 16×4 hit 4292 and 32×8 hit 4583 without ever comparing them as a grid.

```
AutoSA:     search(sa_sizes) → codegen(kernel0) → csim+csynth → rank
This plan:  search(PeRecipe)  → instantiate(compact PE) → csim+csynth → rank
Not this:   LLM × N recipes   (flash already emitted pseudo-code once)
Not this:   clone kernel0
```

Legal points for `autosa_mm` (I=J=K=64, float, 32-bit):

- `pe` in `{8, 16, 32, 64}` and `I % pe == 0`
- `simd` in `{2, 4, 8}` and `K % simd == 0`
- `pack_bits = simd * 32`
- `pe_kj = (K / simd) * J`
- `i_tiles = I / pe`
- `tile_loop = "around_dataflow"` if `i_tiles > 1` else `"inside_tasks"`
- `expected_dsp = pe * simd * 5`
- drop if `expected_dsp > 0.85 * 9024` (U280 DSP cap, same idea as AutoSA 85%)

Candidate id: `pe{pe}_simd{simd}` (example `pe16_simd4`).

```python
# compact_pe_search.py
from __future__ import annotations

from post_flash_pe_recipe import PeRecipe

U280_DSP = 9024
I = J = K = 64
PE_CHOICES = (8, 16, 32, 64)
SIMD_CHOICES = (2, 4, 8)


def candidate_id(rec: PeRecipe) -> str:
    return f"pe{rec.pe}_simd{rec.simd}"


def enumerate_mm_recipes(*, dsp_cap: float = 0.85) -> list[PeRecipe]:
    out: list[PeRecipe] = []
    max_dsp = dsp_cap * U280_DSP
    for pe in PE_CHOICES:
        if I % pe:
            continue
        for simd in SIMD_CHOICES:
            if K % simd:
                continue
            expected = pe * simd * 5
            if expected > max_dsp:
                continue
            i_tiles = I // pe
            rec = PeRecipe(
                bench="autosa_mm",
                pe=pe,
                simd=simd,
                data_kind="float",
                i_macro="I",
                j_macro="J",
                k_macro="K",
                pack_bits=simd * 32,
                expected_dsp=expected,
                min_dsp=max(1, int(expected * 0.6)),
                pe_kj=(K // simd) * J,
                i_tiles=i_tiles,
                tile_loop="around_dataflow" if i_tiles > 1 else "inside_tasks",
                note=f"search point {pe}x{simd}",
            )
            out.append(rec)
    return out
```

`artifacts/pc2/batch_parallel_autosa_mm_32x8_flow_aav_n_gf_20260830_mm32x8/variants/autosa_aav_n_gf/autosa_mm/deepseek-v4-flash__flash__autosa__aav_n_gf/autosa_mm_selected.cpp`

Instantiation rules (deterministic; no LLM):

1. `#define PE_NUM {pe}` and `#define SIMD {simd}`
2. `typedef ap_uint<{pack_bits}> vec_bits;`
3. `packN` / `unpackN` with N=`simd` 32-bit slices
4. `pe_kj` loop trip `(K / SIMD) * J`
5. `i_tiles == 1`: DATAFLOW at function scope (no `i0` wrap); load_A/store_C scan full I
6. `i_tiles > 1`: `for (i0 = 0; i0 < I; i0 += PE_NUM) { #pragma HLS DATAFLOW ... }` as in the 32×8 kernel; `mm_pe` / `load_B` / `drain_B` have **no** tile loop
7. Emit exactly `pe` explicit `mm_pe(...)` calls (DATAFLOW cannot loop on `mm_pe`)
8. Keep the `autosa_mm` ABI and INTERFACE lines
